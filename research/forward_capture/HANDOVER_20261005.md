# Forward candidate capture — engineering handover 2026-10-05

## 1. Question
Can exact common-cycle eligible candidates and symmetric timed endpoints repair the failed historical comparable-control gate?

## 2. Scope and registration
An engineering core and fixed 14-day measurement-pilot candidate, not an activated or confirmatory trial. No private outcome dataset was opened in this build. Prior historical audit results are disclosed in the preceding selection audit. The ongoing model ledger is unchanged.

## 3. Artifacts
`capture.py`, `test_capture.py`, `PROTOCOL.md`, `README.md`, this handover and `HANDOVER_INDEX.md`. File SHA256 values are registered in the public root manifest. Source is stored on Hetzner in `client_learning/crypto_forward_capture_20261005/`; runtime data must be outside that checkout.

## 4. Unit and candidate population
First score-qualified new token within the production scanner's capped/filtered feed, not the entire chain. Common-cycle controls pass basic eligibility and are matched without outcomes, score-component similarity or future information. Later-alerting controls retain their original role. Score-qualified, screened and delivered are distinct.

## 5. Inputs and leakage
Strict whitelisted fields, exact emitted signal-vector consistency, input hashes, source/protocol binding at activation, fresh local receipt times and private exclusions. Unexpected outcome/profit/credential fields are rejected. Real adapter input-hash verification and cycle-health capture are not yet implemented.

## 6. Endpoint definition
Earliest positive finite same-pair market-cap observation received at index+60 minutes through +180 seconds. Resolve only after the window closes. Missing stays missing; this endpoint estimand has no continuous-path coverage certificate and is not a trading return. No retrospective backfill or peak substitution.

## 7. Validation
23 synthetic SQLite tests pass locally and on Hetzner: cohort/control eligibility, age/size/liquidity matching, exclusions, conflicting retries, first qualification, later control alerts, zero matches, score/finite-field consistency, stale/future inputs, whole-cycle rejection, append-only triggers, chain corruption, separate screening/delivery, pair identity, endpoint timing and fixed pilot stop. No production DB, network, credits, trades or ledger outcomes were used.

## 8. Result and limitations
Core engineering gate passes. Runtime-integration gate remains OPEN. This does not establish scanner edge, adequate control density, unbiased endpoint availability, model quality or profitability. Full-chain verification on every core write is correct for small fixtures but needs measured contention/latency and bounded verification strategy before continuous runtime. Input provenance is local receipt time, not independently verified provider knowledge time. SQLite triggers/chain provide local tamper evidence, not privileged-owner security or external anchoring.

## 10. Next gate
Build/review adapters for complete pre-screening cycles, exact private input persistence, separate screening/delivery receipts and shared existing tracker response timestamps. Add count-only status/health, atomic protocol/source-bound activation and fresh-token exclusions; test source-function invariance, failure isolation, DB/resource bounds and passive-fetch comparability. After the fixed pilot, use arrival/coverage/variance evidence to design a separately frozen confirmatory test; no performance verdict or paid service is justified now.
